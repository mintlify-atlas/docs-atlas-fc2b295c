BlockRazor Block Stream delivers confirmed block data to your application with the lowest possible latency, enabling your trading programs to react to on-chain events the moment a block is finalized. Whether you are monitoring signal transactions, executing post-confirmation logic, or tracking account state changes, Block Stream provides chain-native feeds tailored to each network's architecture. Supported chains include Solana, BNB Smart Chain (BSC), and Base.

<Tabs>
  <Tab title="Solana">
    Solana's high-throughput architecture requires specialized streaming approaches. BlockRazor offers two distinct Solana block stream products: **Shred Stream** for the lowest possible raw data latency, and **Geyser Stream** for structured on-chain data across accounts, slots, blocks, and transactions.

    ### Shred Stream

    Shred Stream transmits raw shred data — the smallest unit of block data in Solana's network — as shreds are produced by the leader validator. This means your application receives block fragments before the full block is assembled, giving you the earliest possible view of new on-chain activity.

    **Subscribing to Geyser Stream (Rust)**

    The following example uses the Geyser gRPC plugin interface to subscribe to transaction updates on Solana:

    ```rust
    use yellowstone_grpc_client::GeyserGrpcClient;
    use yellowstone_grpc_proto::prelude::*;
    use std::collections::HashMap;

    #[tokio::main]
    async fn main() -> anyhow::Result<()> {
        let mut client = GeyserGrpcClient::connect(
            "https://geyser.blockrazor.io",
            Some("YOUR_AUTH_TOKEN".to_string()),
            None,
        )?;

        let mut transactions = HashMap::new();
        transactions.insert(
            "client_id".to_string(),
            SubscribeRequestFilterTransactions {
                vote: Some(false),
                failed: Some(false),
                ..Default::default()
            },
        );

        let request = SubscribeRequest {
            transactions,
            ..Default::default()
        };

        let (_, mut stream) = client.subscribe_with_request(Some(request)).await?;

        while let Some(msg) = stream.next().await {
            match msg {
                Ok(update) => println!("Block update: {:?}", update),
                Err(e) => eprintln!("Stream error: {}", e),
            }
        }

        Ok(())
    }
    ```

    **Subscribing to NewBlocks Stream (Go)**

    The following example connects to the BSC NewBlocks stream over gRPC:

    ```go
    package main

    import (
        "context"
        "fmt"
        "log"

        "google.golang.org/grpc"
        "google.golang.org/grpc/metadata"
    )

    func main() {
        conn, err := grpc.Dial(
            "blocks.blockrazor.io:443",
            grpc.WithTransportCredentials(credentials.NewTLS(nil)),
        )
        if err != nil {
            log.Fatalf("Failed to connect: %v", err)
        }
        defer conn.Close()

        ctx := metadata.AppendToOutgoingContext(
            context.Background(),
            "authorization", "Bearer YOUR_AUTH_TOKEN",
        )

        // Subscribe to new BSC blocks
        stream, err := client.SubscribeNewBlocks(ctx, &SubscribeBlocksRequest{})
        if err != nil {
            log.Fatalf("Failed to subscribe: %v", err)
        }

        for {
            block, err := stream.Recv()
            if err != nil {
                log.Fatalf("Stream error: %v", err)
            }
            fmt.Printf("New BSC block: #%d hash=%s\n", block.Number, block.Hash)
        }
    }
    ```

  <Tab title="Base">
    BlockRazor provides two block stream options for the Base network: the standard **GetBlockStream** for confirmed block data, and **GetFlashBlockStream** for pre-confirmation flash block data at an even lower latency.

    ### GetBlockStream

    GetBlockStream delivers confirmed Base block data with low latency. It is suitable for applications that require finalized block data and operate on confirmed state.

    <CardGroup cols={2}>

    ### GetFlashBlockStream

    GetFlashBlockStream provides access to Base's FlashBlock data — partial block information made available before full block confirmation. This stream is designed for latency-critical applications that need to act on block data as early as physically possible.

    <CardGroup cols={2}>
      <Card title="Stream Name" icon="bolt">
        GetFlashBlockStream
      </Card>
      <Card title="Pricing" icon="tag">
        $250 / stream / month
      </Card>
    </CardGroup>

    <Tip>
      Use GetFlashBlockStream when your strategy depends on reacting to Base block data before competing participants. The lower price combined with earlier data delivery makes it the preferred option for most latency-sensitive Base integrations.
    </Tip>
